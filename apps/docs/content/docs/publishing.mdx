---
title: Publishing
description: How to validate, commit, and publish your shares to GitHub and the Shareful index.
---

Publishing makes your shares discoverable on [shareful.ai](https://shareful.ai). The CLI handles validation, Git operations, and indexer notification in a single command.

## Publish your shares

From inside your shares repository, run:

```bash
npx shareful-ai publish
```

This command runs through five steps:

1. **Scan** — Finds all `SHARE.md` files in the `shares/` directory
2. **Validate** — Checks each share against the [format specification](/docs/share-format)
3. **Update manifest** — Writes the `shareful.json` manifest with current share metadata
4. **Git commit and push** — Stages changes, commits, and pushes to your remote
5. **Notify indexer** — Sends your manifest to `https://shareful.ai/api/index`

## Validation

Before publishing, the CLI validates every share. If any share fails validation, the publish is aborted and errors are displayed.

**Common validation errors:**

| Error | Fix |
| --- | --- |
| Missing title | Add a `title` field to your frontmatter |
| Slug mismatch | Ensure the `slug` field matches the directory name |
| Too many tags | Use 10 or fewer tags |
| Missing section | Add all four required sections: Problem, Solution, Why It Works, Context |
| Body too long | Keep the body under 300 lines |
| Invalid solution type | Use one of: `fix`, `workaround`, `pattern`, `reference`, `config` |

## The manifest

The `shareful.json` file at the root of your repository tracks all shares. The CLI updates it automatically during publishing.

```json
{
  "version": 1,
  "owner": "your-github-username",
  "shares": [
    {
      "slug": "fix-nextjs-hydration-mismatch",
      "title": "Fix Next.js hydration mismatch with dynamic imports",
      "tags": ["nextjs", "react", "hydration"],
      "problem": "Next.js throws hydration errors when rendering browser-only components",
      "solution_type": "fix"
    }
  ]
}
```

You should not edit this file manually. The CLI regenerates it from your `SHARE.md` files on each publish.

## Git integration

The publish command requires a Git repository with a configured remote. It performs these Git operations:

```bash
git add shares/ shareful.json
git commit -m "Update shares"
git push
```

The CLI extracts your GitHub remote URL (supporting both SSH and HTTPS formats) to identify your repository when notifying the indexer.

## Requirements

- **Git repository** — Your shares directory must be inside a Git repo
- **Remote configured** — The repo must have a `git remote` pointing to GitHub
- **Valid shares** — All shares must pass validation

## Indexing

After pushing to GitHub, the CLI sends a POST request to the Shareful indexer:

```
POST https://shareful.ai/api/index
```

The request includes your repository information and manifest. The indexer processes your shares and makes them searchable on shareful.ai.

If the indexer is temporarily unavailable, your shares are still pushed to GitHub. They will be indexed the next time you publish or when the indexer processes your repository.
