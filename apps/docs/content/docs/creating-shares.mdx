You'll learn how to create shares from start to finish, including the interactive workflow, CLI flags for automation, and tips for writing useful content.

## Quick start

Run the create command from inside a shares repository:

```bash
npx shareful-ai create
```

The CLI prompts you for each required field:

1. **Title** -- A clear, specific title for your solution
2. **Problem** -- A one-sentence description of the issue
3. **Solution type** -- Choose from `fix`, `workaround`, `pattern`, `reference`, or `config`
4. **Tags** -- Relevant keywords for discoverability

After completing the prompts, the CLI generates a `SHARE.md` file in `shares/<slug>/SHARE.md` with your frontmatter pre-filled and section templates ready to complete.

## Using CLI flags

Skip the interactive prompts by passing all four flags directly:

```bash
npx shareful-ai create \
  --title "Fix ESLint flat config migration" \
  --problem "ESLint 9 flat config breaks existing plugin configurations" \
  --tags "eslint,config,migration" \
  --type fix
```

This is useful for scripting or when you already know the metadata.

## Writing the body

After the CLI generates the file, open it and fill in the four required sections: Problem, Solution, Why It Works, and Context.

For detailed templates, must-include elements, and anti-patterns for each section, see the [share format specification](/docs/share-format#body-sections).

The key principles:

- **Problem** -- Show the broken code and error message, not a description of the fix
- **Solution** -- Provide complete, runnable code with language labels on every code block
- **Why It Works** -- Explain the root cause in prose, don't just restate the solution
- **Context** -- Use a bulleted list with version requirements first

## Choosing the right solution type

Pick the solution type that best matches how your share addresses the problem.

| Type | Use when... |
| --- | --- |
| `fix` | You found a direct solution to a bug or error |
| `workaround` | The upstream issue exists but you found a way around it |
| `pattern` | You're sharing a reusable approach or best practice |
| `reference` | You're documenting configuration, setup, or reference material |
| `config` | The solution is primarily about configuration files or environment setup |

## Writing tips

Follow these principles to make your shares useful and discoverable.

**Be specific.** "Fix React error" is too vague. "Fix React hydration mismatch when using browser-only libraries with Next.js 14" tells readers exactly what this solves.

**Include complete code.** Partial snippets frustrate readers. Show the full file or function, not just the changed line.

**Add error messages.** People search for error messages verbatim. Including the exact error text makes your share more discoverable.

**Keep it focused.** One share solves one problem. If you have multiple solutions, create multiple shares.

**Tag thoughtfully.** Use specific, lowercase tags. Prefer `nextjs` over `next` and `typescript` over `ts`. Include the framework, language, and key libraries involved.

**Start the title with the right verb.** Match the verb to your `solution_type`: "Fix" for fixes, "Use" or "Implement" for patterns, "Configure" for configs.

## Validate before publishing

Run `npx shareful-ai check` to validate all shares in your repository. The CLI checks frontmatter fields, body sections, and slug-directory alignment.

Quick validation checklist:

- Title starts with a verb matching `solution_type`, under 128 characters
- Slug matches the parent directory name, lowercase with hyphens only
- Tags are 1-10 items, all lowercase
- Problem includes the error message or observable symptom
- All four body sections present in order
- Body is under 300 lines
- No placeholder content

For the complete checklist, see [examples](/docs/examples#quality-checklist).
